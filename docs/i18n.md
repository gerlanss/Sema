# Language And Identifiers

Public Sema documentation is English.

Do not translate commands, file paths, package names, endpoint paths, environment
variable names, code symbols, DSL keywords, or brand names.

Examples:

- Keep `sema validar`, not an English paraphrase.
- Keep `.sema`, `task`, `input`, `output`, `rules`, `effects`, and `guarantees`.
- Keep package names such as `@semacode/cli`.

Human-facing prose should be clear English. Contract DSL can keep its own
keywords and domain identifiers.
